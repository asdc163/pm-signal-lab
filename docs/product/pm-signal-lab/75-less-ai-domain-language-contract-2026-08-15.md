# PM Signal Lab — Less-AI Domain Language Contract — 2026-08-15

## Decision

Remove the remaining generic AI vocabulary from the working flow after the loaded title. The product should read as a source-review worksheet for an AI-assisted support draft, not as a copilot product wearing a field-notebook skin.

Keep `AI-assisted support drafting` in the explicit subject-under-review cue and in the portfolio README. In the task flow, use the concrete objects people actually handle: `support draft`, `source`, `claim`, `limitation`, `smallest test`, and `decision brief`.

This is a reversible copy/domain-language slice. It does not add a model, provider, login, telemetry, persistence, upload, automatic issue submission, or growth claim.

## Product Craft Contract

### Problem frame

- **User/job:** An international PM, founder, designer, or engineer wants to inspect one product signal, decide what it can support, and leave with a smallest test that another person can challenge.
- **Current workaround:** The observed line, source link, interpretation, and experiment brief live in separate notes; a polished AI label can become the subject instead of the product question.
- **Current product truth:** PM Signal Lab is a deterministic, local-first worksheet. The public sample is fictional. It does not run a live model or submit a GitHub issue.
- **Current defect:** The loaded title was corrected, but Verify and Decide still repeat `support copilot`, `assistant draft`, and `AI support-copilot pack`. The user can still feel they entered an AI demo rather than a PM working paper.
- **Decision:** Make the visible working vocabulary concrete and domain-led; retain AI only where it explains the subject under review or portfolio relevance.
- **Success metric:** In the loaded browser trace, the visible task and domain objects remain understandable when the generic AI labels are removed. The old generic strings must be absent from the application bundle; the subject cue must remain present.
- **Out of scope:** Non-owner comprehension, model quality, real support operations, Chrome Extension sign-off, native screen-reader sign-off, adoption, traffic, GitHub stars, and the 10,000-star outcome.

## Product Messaging Contract

### Message Job

- **Decision:** Does this line describe the work object the PM is handling, or does it merely advertise an AI category?
- **User job:** Move from an observed line to a defensible next test.
- **Target action:** Open the source, review the claim, draft the test, or inspect the brief.
- **Success metric:** The user can name the current object and next action without relying on an AI persona.

### Source Truth

- **Product truth:** deterministic local worksheet; fictional source lines; explicit limitations; manual export.
- **User language:** `support draft`, `source line`, `what this line supports`, `smallest test`, `decision brief`.
- **Proof:** source identity/date/excerpt, claim status, limitation, human action, local boundary, and `Not covered` export block.
- **Not covered:** live provider output, real support resolution, adoption, market preference, and stars.

### Positioning

- **Category:** source-linked PM decision worksheet.
- **Alternative:** a chat transcript or loose notes copied into an experiment template.
- **Differentiated mechanism:** keep source, claim, limitation, human review, and smallest test in one field folio.
- **Reason to believe:** the public demo exposes source rows, evidence mapping, missing-evidence state, and manual handoff directly.
- **Not for:** treating a deterministic sample as model validation or automatic GitHub submission.

### No-AI Copy Guard

- Keep `AI-assisted support drafting` only in the explicit subject cue and portfolio framing.
- Prefer `support draft` over `support copilot` in task copy.
- Prefer `support draft` over `assistant draft` when naming the reviewed work.
- Prefer `support-draft worksheet` over `AI support-copilot pack` in experiment instructions.
- Do not replace concrete evidence with vague promises such as `smart`, `seamless`, `powerful`, or `intelligent`.
- Do not hide the AI relationship completely; doing so would weaken the intended AI-PM portfolio signal.

## Composition Brief

- **First read:** `Check what this line supports` and the current step.
- **Second read:** the support-draft worksheet title, subject cue, source ledger, and source limitation.
- **Primary action:** one step-specific action, ending in `Export decision brief` or `Open pilot note`.
- **Content relationship:** `Source → Claim → Smallest test`; use rows, ruled sections, and definition lists before adding containers.
- **Density:** medium-high on desktop for review; stacked medium on mobile.
- **Alignment spine:** topbar → task title → working file → source/claim rows.
- **Signature detail:** red correction mark plus blue provenance spine.
- **What not to use:** copilot language as a task label, assistant persona, gradient/orb/glass/bento decoration, or fake processing state.

## UX State and Trust Gate

- **First-time / empty:** explain the worksheet job before mentioning AI; provide `Open the sample worksheet`.
- **Loading:** say the worksheet is opening; do not simulate model thinking.
- **Loaded:** show the PM task, support-draft object, subject cue, source, and limitation in that order.
- **Verify:** make claim status and source mapping visible; human accepts, edits, keeps as hypothesis, or marks missing evidence.
- **Decide:** show metric, guardrail, smallest test, decision rule, and owner; no phrase may imply the brief is validation.
- **Ship / recovery:** export remains manual; refresh clears local state; feedback privacy gate blocks unsafe preparation.
- **Mobile / accessibility:** preserve the single-column reading path, sticky action, visible focus, semantic names, and readable text expansion.
- **AI uncertainty:** retain source freshness, missing evidence, limitations, and `Not covered`; no live model or confidence score is claimed.

## UX/AI/security gate

- **UX gate:** First-time, empty, loading, error, recovery, mobile, keyboard focus, source expansion, and export states must continue to expose the next human action. No state may imply that a model is thinking or that a draft is already validated.
- **AI gate:** The only visible AI label in the working surface is the subject cue `AI-assisted support drafting`; task copy must use the reviewed objects and preserve uncertainty, source freshness, and `Not covered`.
- **Security/trust gate:** Keep the existing private-data/token block, synthetic-feedback privacy checkbox, local-only boundary, no-upload/no-telemetry behavior, and manual export warning. Do not add secrets, providers, permissions, or automatic external writes.
